# tool-timetable

연구실 주간 시간표를 **끌어서 그린다**. 사람은 색, 일정의 종류는 무늬로만 구분한다.

칠판에 그린 시간표를 매주 다시 그리던 작업을 대체한다.

## 클릭 예산: 2 (인원 추가 → 드래그)

묻지 않고 정하는 것:

| 항목           | 결정 방식                                                                  |
| -------------- | -------------------------------------------------------------------------- |
| 색             | dartwork-mpl 인쇄 8색을 순서대로 자동 배정 (나중에 바꿀 수 있되 필수 아님) |
| 시간 범위      | 09:00–21:00 고정                                                           |
| 요일           | 월–금                                                                      |
| 스냅           | 30분                                                                       |
| 저장           | 브라우저에 자동 저장 (저장 버튼 없음)                                      |
| 새 막대의 무늬 | 실선(고정 일정). 클릭으로 빗금과 오간다                                    |

## 실패 체크리스트

- [x] 드래그 시작·끝이 모두 30분 경계에 스냅된다
- [x] 아래에서 위로(역방향) 드래그해도 같은 범위가 만들어진다
- [x] 막대 끝을 잡아 늘이면 반대쪽 끝은 움직이지 않는다
- [x] 09:00 위 / 21:00 아래로 끌어도 범위를 벗어나지 않는다
- [x] 같은 사람·같은 요일에서 겹치는 막대는 하나로 합쳐진다
- [x] 맞닿은 막대(끝==시작)도 하나로 합쳐진다
- [x] 인원을 지우면 그 사람의 막대가 함께 사라진다
- [x] 새로고침해도 그대로다
- [x] 인원 8명(팔레트 전량)에서도 레인이 뭉개지지 않는다
- [x] PNG 내보내기가 화면과 같은 배치를 낸다 (제목 배너 + 이름표 + 막대)

`[x]` 는 `*.spec.ts` 로 자동 검증된다.

```sh
pnpm test
```

"새로고침해도 그대로다"는 `storage.spec.ts` 가 저장 → 복원 왕복으로 덮는다. 새로고침이
하는 일이 그것이기 때문이다. PNG 는 사람이 눈으로 봐야 한다 — 화면과 같은지는 픽셀
비교가 아니라 판단의 문제다.

## 이렇게 읽는다

세로가 시간, 가로가 요일이다. 요일 열 하나 안에 **사람 수만큼의 세로 레인**이 인원
목록과 같은 순서로 선다. 같은 사람은 어느 요일에서나 같은 자리에 있으므로, 막대에
이름을 쓰지 않아도 색과 위치로 읽힌다. 막대에는 글자가 없다.

- 빈 레인을 끌면 막대가 생긴다. 위아래 어느 방향으로 끌어도 된다.
- 막대의 끝을 잡으면 늘고 줄고, 몸통을 잡으면 옮겨진다.
- 막대를 누르면 무늬가 실선 ↔ 빗금으로 바뀐다. 실선은 고정 일정, 빗금은 그 밖의 것 —
  뜻은 쓰는 사람이 정한다.
- 겹치거나 맞닿은 막대는 손을 떼는 순간 하나로 합쳐진다.

## 구조

순수 로직을 먼저 쓰고 테스트로 굳힌 뒤 UI 를 얹었다. `time`·`schedule`·`layout` 셋은
Svelte 도 DOM 도 모르고, 그래서 화면과 PNG 가 같은 규칙을 나눠 쓸 수 있다.

| 파일              | 역할                                               |
| ----------------- | -------------------------------------------------- |
| `src/time.ts`     | 시간 ↔ 슬롯 변환, 30분 스냅, 역방향 정규화, 클램프 |
| `src/schedule.ts` | 사람·막대 도메인, 레인 병합, 저장용 직렬화·검증    |
| `src/layout.ts`   | 그리드 가로 배치 (화면과 PNG 가 공유)              |
| `src/storage.ts`  | localStorage 자동 저장                             |
| `src/png.ts`      | canvas 에 직접 그리는 PNG 내보내기                 |
| `src/App.svelte`  | UI. `ui/` primitive 로만 조립                      |

**PNG 는 화면을 캡처하지 않고 직접 그린다.** html2canvas 같은 의존을 들이지 않은
이유는 두 가지다: 이 시간표는 사각형과 선뿐이라 직접 그리는 편이 정확하고, 의존이
0 이면 툴박스가 이 툴을 실을 때 따라오는 짐도 없다. 대신 화면과 PNG 가 **같은
`time.ts` 눈금과 같은 `layout.ts` 폭 규칙**을 쓰게 해서 두 그림을 붙들어 둔다.

색도 마찬가지다. PNG 는 CSS 를 모르므로 색값을 넘겨야 하는데, 값을 두 번 적는 대신
`.tool-root` 의 계산된 토큰을 그대로 읽는다. 호스트가 테마를 덮어쓰면 PNG 도 따라간다.

## 배포 상태

껍데기가 둘이고 동작은 하나다.

| 껍데기        | 어디에                           | 진입점                               |
| ------------- | -------------------------------- | ------------------------------------ |
| 툴박스 임베드 | `betlab-toolbox` 의 `/timetable` | `src/index.ts` 의 `manifest` + `App` |
| 단독 사이트   | 자기 URL (Vercel, 정적 프리렌더) | `app/` + `svelte.config.js`          |

`manifest.surface` 는 `'embed'` 그대로다 — 툴박스는 계속 안에서 렌더한다.
단독 배포는 그 위에 표면을 하나 더 얹은 것이지, 임베드를 대체한 것이 아니다.

```sh
pnpm install && pnpm build   # .vercel/output/static — 서버 없는 정적 산출물
pnpm dev                     # 단독 껍데기로 띄워 보기
```

`app/` 에는 **동작이 없다.** 툴박스에 실리면 `app/` 은 존재하지 않으므로, 여기 기능을
넣으면 임베드에서 조용히 사라진다. 라우트는 `App` 을 렌더하는 세 줄이 전부이고,
헤더는 manifest 에서 이름과 아이콘만 가져다 그린다.

계약 토큰(`--betlab-*`)도 `app/` 에서 정의하지 않는다. 정의하는 순간 호스트가 테마를
덮어쓴 셈이 되어, 단독 실행에서 툴 자신의 기본값(`src/ui/theme.css` 의 폴백)이
안 쓰인다. 껍데기는 `body` 의 여백·배경·높이까지만 정한다.

사람 팔레트(`--person-0 … --person-7`)를 포함해 색값은 `src/ui/theme.css` 한 곳에만
있다. 도메인은 "몇 번 칸"인지만 알고 색이 무엇인지는 모른다.

런타임 의존(`svelte` · `@lucide/svelte` · 폰트)은 `peerDependencies` 로 요구를 밝히고
— 툴박스가 단일 버전으로 설치한다 — 단독 빌드가 혼자 서도록 `devDependencies` 에도
같이 적어 둔다. `dependencies` 는 비운다.
